# Design process

The practice behind the UI rules. Load when running a design project, evaluating a screen, or breaking a creative block.

## The one-line process

Research what people need. Synthesize into a clearly-framed problem. Ideate many options. Build cheap prototypes. Test with real users. Learn and repeat.

## Stages

1. **Discovery and research.** Study real target users, not your team. Qualitative first to understand, quantitative to confirm. Open, non-leading questions. Watch behavior over stated opinion. Triangulate the why, the how many, and the actual behavior.
2. **Synthesis.** Build personas, jobs-to-be-done, and journey maps from research data. Map the current experience before the future one. Keep one to three crisp personas. Reference the persona in every review.
3. **Information architecture and flows.** Label with the user's words. Group and name content the way users predict. Keep the top level of nav small. Validate with card sorting and tree testing. Draw task flows before screens. Plan the error and edge branches, not just the happy path.
4. **Wireframes and prototypes.** Match fidelity to the question. Sketch to think, low-fi to align, hi-fi to test. Put real words in wireframes. Prototype several options in parallel. Test the prototype with users.
5. **Interaction design.** Design every state: rest, hover, active, loading, empty, error, success. Give every action feedback. Make destructive actions reversible with undo. Keep the same control meaning the same thing everywhere. Design for the mental model the user already has.
6. **Visual craft.** 4px spacing grid. Consistent alignment. Small type scale with clear tiers. One accent color used sparingly. One coherent system for borders, shadows, radii. Real photography and specific imagery.
7. **UX writing.** Verb plus object for buttons. Empty states with context, cause, action. One tone across every screen. Draft the words in the wireframe.
8. **Usability testing.** About 5 users per round, then re-test after fixes. Realistic scenario tasks. Observe behavior, not just stated opinion. Write research questions before the tasks.
9. **Critique.** Set a clear scope. Agree on design objectives before giving feedback. Frame feedback against the objective.
10. **Metrics.** SUS, completion rate, time-on-task, error rate, satisfaction. Baselines required.

## Creativity

### Foundations

- Divergent and convergent thinking are different modes. Do not blend them in the same moment.
- Hold several tentative options in parallel instead of committing early.
- Novelty is only useful if it is grounded in the user's need.

### Ideation methods

- SCAMPER: substitute, combine, adapt, modify, repurpose, eliminate, reverse.
- "How might we" questions to reframe needs.
- Analogy to import structure from a different field.
- Re-expression and extreme personas to break framing.
- "What if this rule were false" to break assumptions.
- Brainwriting or 6-3-5 when one voice dominates.
- Generate the worst possible idea to relax judgment.

### Cognition and blocks

- Schedule time away for incubation.
- Pull in off-beat input to break a stale frame.
- Build psychological safety so wild ideas survive.
- Use a different method when the same one keeps producing the same result.
- Force creative work in a rushed, overloaded state and the output dies.
